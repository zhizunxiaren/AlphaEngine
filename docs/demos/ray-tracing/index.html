光线追踪，到底在干什么

一句话：把眼睛当相机，倒着追光。每个像素射出一条光线，然后问它——「你看到了什么？」。 下面每一节都有一个可以动手拖的演示，建议按顺序过一遍；最后一节是真的在跑一个路径追踪器。

先给结论

光栅化问的是：「这个三角形覆盖了哪些像素？」——以物体为起点，往屏幕推。

光线追踪问的是：「这个像素看到了什么？」——以像素为起点，往场景里追。

方向反过来之后，三件事变得极其自然，而在光栅化里需要大量技巧才能模拟：

能力为什么反向之后免费
阴影从交点朝光源再发一条光线，中途打中东西就是阴影
镜面反射 / 折射沿反射定律再发一条光线，递归下去即可
全局光照（间接光）在表面随机撒一条光线，连续弹射，红墙绿墙的相互染色自动出现
代价也很清楚：一个像素一条光线通常不够——要发几百上千条取平均。这就是路径追踪慢、有噪声的根本原因，也是本项目后续要处理的核心问题。
1

它和光栅化差在哪

下面两边是同一个三角形、同一块屏幕、同一份输出图像。唯一的差别是到达的方式：左边从几何出发投影，右边从像素出发追光。注意看最后两块小图——结果完全一样。

光栅化：几何 → 投影 → 覆盖哪些像素
光线追踪：像素 → 射线 → 打到谁
左边的瓶颈是「遮挡」：每个像素只能填最近的那个三角形，于是有了深度缓冲（z-buffer）。右边的代价是「次数」：每个像素都要独立求交，于是有了 BVH 加速结构。两者都在补自己方向的短板。
2

一条光线 = O + t·D

整个光线追踪里最基础的一行字。圆点 O 是起点，箭头 D 是方向，t 是一个标量参数。拖动箭头尖端改变方向，拖动滑杆改变位置——点 P 永远沿着这条直线跑。

P(t) = O + t·D    // t < 0 → 相机背后，要丢掉；t > 0 → 前方，才可能被看见
t 不是距离。只有在 |D| = 1 时 t 才等于欧氏距离。方向若由「像素位置 − 相机位置」直接给出，a = |D|² ≠ 1，t 只是参数。这直接影响 t_min / t_max 怎么取值——笔记里专门记了这条坑。
3

求交：光线打中球了吗

「打中了没有」这个问题，等价于：把光线方程代进球面方程，看这个一元二次方程有没有实根。推导只有三步：

球面： |X − C|² = r² 代入： X = O + t·D 展开： t²(D·D) − 2t(D·oc) + (oc·oc − r²) = 0    // oc = C − O 记作： a·t² − 2h·t + c = 0

关键洞察：判别式比根更重要。渲染中最常问的不是「交点在哪儿」，而是「到底有没有交点」——Δ < 0 就可以立刻跳过这个物体。几何求交的性能优化，几乎全部建立在这一步的提前退出上。
两个常见的写错点：① 起点在球内部时（c < 0）近根为负，必须回退到远根，否则相机一进球里就什么都看不见；② 筛选必须是开区间 t_min < t < t_max，写成闭区间会在边界处重复命中自己。
4

法线 → 第一个有立体感的球

求交之后我们手里有一个交点 P。把它变成「一个球」需要的东西只有一样：表面法线。球面法线不需要额外计算——交点减球心，再除以半径就归一化了。

N = (P − C) / r    // |P−C| = r，所以除完天然是单位向量
color = 0.5 · (N + 1)    // 把 [−1,1] 的向量映射到 [0,1] 的颜色

就这两行，你已经得到了原书里第一个能看的球。下面是真的在逐像素跑（拖动旋转，或用按钮切换着色方式）：

「图像是一行一行出来的」不是比喻。原书里渲染就是外层 for j（行）、内层 for i（列），一个像素一个像素算出来的。点上面的按钮可以重看一遍这个过程。
为什么用 (N+1)/2 而不是 N？因为颜色不能是负数。法线的每个分量都在 [−1, 1]，而颜色必须在 [0, 1]；(N+1)/2 正好是一次线性映射。这也是后面所有着色公式的起点——光照模型本质上就是「把法线变成一个数字」的不同方式。
5

弹射的账本：albedoⁿ

前面是「一条光线只问一次」。真实感的来源是接着问下去：光线打到球上之后，从那个点朝某个方向再发一条，问「那个方向有多少光？」。这个值我们记作 Lin。

这是最容易误解的地方：递归不产生光，只查询光。球不是被「绘制」出来的对象，它是一个无状态的查询函数——相机不问，它就不存在。

每弹一次，颜色就要乘一次该表面的反射率（albedo）。所以整条链的结果是：

最终颜色 = albedo₁ × albedo₂ × … × albedoₙ × 光源   // n = 逃逸前的命中次数
为什么深度不需要设得很大？看这张表——albedo 稍微小于 1，连乘很快就衰减到看不见了：
命中次数 n系数（albedo = 0.5）实际效果
01.0直接看到天空
10.5亮度减半
50.031已经很暗
109.8 × 10⁻⁴几乎不可见
508.9 × 10⁻¹⁶等于黑
所以 max_depth 到顶返回黑色，不是 bug，是「保险丝」。它的作用只是防止光线被卡在几何体之间无限递归爆栈。正常出口永远是「光线逃逸到天空」那一支。

一条光线怎么穿过金属球和玻璃球

先看金属球那一步：入射角 = 反射角，这是唯一规则。 光线以 58.50° 打到球面，就以 58.50° 弹开（都相对法线量）。偏折量是 180° − 2 × 58.50° = 63.00°。 注意命中点在球的上表面——正因为法线朝上，斜射进来的光才可能被「顶」回右上方向。 控制这个的是法线朝向，不是「球会反弹」这种拟人说法。
金属：Dout = D − 2(D·N)N   // |D| 与 |D_out| 都为 1，所以 D·N = −cosθ
再看玻璃球：这里要换「介质」，所以要用 Snell 定律。 光线从空气（n₁ = 1.0）以 50.00° 入射，进入玻璃（n₂ = 1.5）后折射角变成 30.71°—— 光线向法线靠拢，这正是「光在密介质里被掰弯」的量化形式：
n₁ · sin θ₂ = n₂ · sin θ₂ₜ  →  1.0 × sin 50.00° = 1.5 × sin 30.71°  →  0.7660 = 1.5 × 0.5107 ✓
球内那一段弦，藏着一个必须讲清楚的结论。 光线在球内走的是弦，弦的两个端点分别在球面上。因为两端到球心的距离都等于半径 r， 「球心—入射点—出射点」构成等腰三角形，所以这条弦与两个端点的法线夹角必然相等。 把 Snell 定律反过来用一次，就得到：
出场入射角 θ₃ ≡ 入场折射角 θ₂ₜ = 30.71°   // 不是巧合，是等腰三角形的必然结果 弦长 = 2r · cos θ₂ₜ = 2 × 1.20 × cos 30.71° = 2.063
由此可以顺手纠正一个很常见的错误想象：「光在玻璃球里会来回全反射，永远出不来」。 不会。从外部射入球体的光线，在球内永远不可能发生全内反射。理由是硬的： 上一条等式已经证明内壁入射角恒等于入场折射角 θ₂ₜ，而 Snell 定律给出 |sin θ₂ₜ| = sin θ₂ / n ≤ 1/n，于是 θ₂ₜ ≤ asin(1/n) = asin(1/1.5) = 41.81°—— 这个上界恰好就是临界角本身，只在掠入射（θ₂ → 90°）时才取等号。 也就是说：内壁入射角永远「刚好够不着」临界角，全内反射的条件根本触发不了。 真正会出现全内反射的场合，是光线已经在玻璃内部（比如从玻璃球内部射出，或从水下看水面），这是两个完全不同的初始条件。
把「分光」勾上，会看到玻璃球两个表面上各多出一条很暗的反射分支。 这是真实的 Fresnel 行为——玻璃不是全部透射，在 50° 入射时约 5.8% 被反射回去 （用 Schlick 近似或完整 Fresnel 公式都能算出这个量级）。 主光路是那条约 94% 的透射光；金属那边则相反，绝大多数能量都被吸收/反射掉，几乎不透明。 「金属」和「玻璃」的差别不在几何，全在这一次分光比例上。
为什么这一节用「侧视剖面」而不是渲染出来的球？ 因为 3D 渲染图里光线会被前景挡住、折射会让交点看起来「飘」在外面，很难对上号。 剖面图把所有东西摊在同一个平面上，交点、法线、角度都是可以直接量的。 §6 那个渲染器处理的是同一套物理，只是每条光线都换成了几百万条、而且每次弹射的材质系数还要逐次相乘——这也正是 §6 的图那么慢的原因。

一条光线会被弹几次

§7 那条路径很长，是因为它恰好把两颗球都打了一遍——先被金属弹开，再穿进玻璃、穿出玻璃。 但这属于少数情况。把相机朝前转半圈会发现：三分之二的方向什么也碰不到，直接离开了场景； 而像 §7 那样弹三次的方向，只占 1.9%。

这一节要补齐的就是 ray_color 里那个 else 的另一半： 没打中时返回什么？打中一次、两次、三次又分别停在哪里？什么时候会被强行截断？ 场景、眼位、两颗球的位置与 §7 完全相同，唯一改变的是发射方向 α 和弹射预算 max_depth。

还要补上 §7 漏掉的另一半：玻璃表面并不是「光一定穿过去」。 它按 Fresnel 定律把光分成两支——反射走 R、折射走 1−R。 所以「这条光线弹了几次」严格说不是一个数，而是一棵带概率的树； 本节把每个玻璃命中点的反射支也画出来（橙色虚线）、列进右侧分支表， 并在扫描带下面把反射率随方向的变化画成一条曲线。

原书 ray_color 的骨架就是这个 if / else——命中次数不是「结果」，是「递归深度」。 每次打中表面，就把「我看到什么」这个问题换到交点上再问一遍；问题是同一个，起点变了。 所谓「弹射 3 次」，就是这条链子连着问了 3 次，第 4 次问到了空处（背景色），于是层层返回、逐层乘上材质系数。
if (world.hit(r, t_min, t_max, rec))  // 打中了 → 换个起点继续问     return attenuation × ray_color(new_ray, depth − 1); return sky_color(unit_direction)  // 没打中 → 背景色，链子到此为止 // 而 max_depth 是给这条链子上的保险丝： if (depth <= 0) return color(0, 0, 0)  // 预算用尽 → 黑，不再往下问
为什么 §6 那个渲染器必须打几百万条光线？看看这条方向轴就明白了。 单条光线弹得越多次，它对最终像素颜色的贡献链条就越长。而在这套几何里： 0 次命中占 65.9% 的方向，1 次占 17.5%，2 次占 14.7%，3 次只有 1.9%。 也就是说，随机撒出去的光线里，绝大多数一条材质系数都没乘上就返回了背景色； 真正承载「金属 + 玻璃」信息的那一小撮，只占不到 2%。 想让画面稳定，就得把这一小撮的贡献采样足够多次——这就是 §6 要累积成百上千轮的原因。
「命中两次」那条值得单独看一眼：它自己证明了 §7 的结论。 这条光线从空气以 40.80° 斜射进玻璃，折射后变成 25.82°；在球内走完弦， 从另一侧出来时入射角恰好又是 25.82°，折射回空气正好回到 40.80°—— 两端完全对称。这不是凑出来的，正是 §7 那个「球心—入射点—出射点构成等腰三角形」的必然结果。 所以玻璃球永远不会把光「困」在里面：进去多少角度，出来还是多少角度。
但上面每一个「命中几次」，都只是这条光线若干种走法里概率最大的那一种。 金属球是理想镜面，方向唯一；玻璃表面却不是——它按 Fresnel 把光分成两支： 反射走 R、折射走 1−R，两支都要继续问下去。所以 α = −38° 那条标称「3 次命中」的路径， 实际只覆盖了 88.80% 的光：另有 5.77% 在入场那一刻就被表面反射掉 （只打 2 次，颜色链是「背景色 × 金属 × 玻璃」，压根没有第二次折射）， 还有 5.12% 在出场面被反射回球内、多走一条弦再出来（打 4 次）。
这就是「把因素考虑全」的意思：每条分支的概率 = 沿途各表面 R 的连乘， 而 ray_color 最终返回的是这些分支的加权平均。§6 那个渲染器每条光线 「随机选一支」正是为了用样本把这个平均积出来。
一个漂亮的巧合（在这六条示范路径上严格成立）：期望命中次数 = 只走折射分支时的命中次数。 取 p = R = 5.77%、q = 1−p。入场反射那支概率 p，命中数 2（金属 + 这次入场）， 贡献 2p；入场折射那支进球后要「内反射 k 次再出射」， 命中数 3 + k、概率 q·pk·q，求和得 Σ q²pk(3+k) = 3q + p。 合起来 E = 2p + 3q + p = 3q + 3p = 3——恰好等于只走折射分支的那个 3。
直观说：2 次那支比 3 次少 1，4 次那支比 3 次多 1， 而两支的概率正好由 p 与 q 配平，偏差互相抵消了。所以「只数折射分支」在均值上确实不算错。 但它丢掉了方差、丢掉了额外的线段，也丢掉了颜色链。而且一般方向上这个等式会破： 反射出去的那支可能又打中别的物体。本页扫过整条方向轴，最大偏差 0.41 次， 正好出现在掠射附近——那时反射率高达 70%，被反射走的光又撞上了金属球。
扫描带那四条笔直的边界，在真实渲染里是软的。 球心方向附近的正入射只有 4.00%（正是 Schlick 的极限值 ((1−1.5)/(1+1.5))² = 0.04），但只要入射角往 90° 靠， R 就一路飙上去：60° 时 8.9%、80° 时 38.8%、89° 时 90.4%。
而「往 90° 靠」在几何上就等于靠近玻璃球的轮廓——所以玻璃球边缘那一圈 永远是亮的（Fresnel 边缘增亮），而且掠射的光几乎全被反射走、几乎不折射。
这正是扫描带下面那条曲线的形状：球心附近趴在 4% 上， 两端冲向高处。它说明「命中 2 次 / 3 次」这些分类在边界附近会糊掉—— 真实渲染里那里是两支混在一起的，只有本页这种「只走折射」的示意才会得到刀切一样的分界。
别把「弹射次数」和「有几个交点」混起来——这是两个不同的问题。 §3 讲的 Δ 判别式回答的是「这条光线与这一颗球有几个交点」：Δ < 0 一个没有、 Δ = 0 恰好相切一个、Δ > 0 两个。而这一节讲的「命中几次」是「这条光线一路问了几次」， 是在多颗物体、多次反弹之间累加的。
两者的关系只有一个：线在球面上命中一次，才可能产生一次新的弹射。 相切（Δ = 0）这种「刚好擦过」的情况是测度为零的事件、数值上也不稳定， 所以本页不把它做成动画——它属于 §3 那张 f(t) 抛物线要讲的事，不是本节要讲的事。

五个常见误区

① 「光线追踪就是全局光照」
不是。基础版只做「直视 + 简单反弹」，实际能力介于直接光与完整全局光之间。真正的全局光照要解决的是渲染方程的完整积分——那是另一个量级的工程问题。
② 「光线是从光源发出的」
真实的物理光路确实如此，但从光源出发做计算是死路：一个像素占据的立体角可能只有 10⁻⁸，发一亿条光线也可能一条都打不中相机。所以实际做法是反向追踪，靠的是光路可逆性（Helmholtz 互易性）：同一条折线反着走，光量不变。
③ 「一个像素发一条光线就够了」
一条光线只能回答「这一个方向有多少光」。抗锯齿需要多条（像素内抖动），软阴影需要多条（朝光源区域抖动），全局光照需要多条（半球随机方向）。「多条取平均」不是可选的优化，它是渲染方程唯一的求解手段。
④ 「交点自己会发光」
初学者最容易带走的一个错误直觉。ray_color 的返回值永远是同一个量：从光线方向入射到起点的光量。命中表面不是终点，是「换到那个点，继续追问光的来源」。混淆这一点，在做直接光采样（NEE）时会彻底找不到北。
⑤ 「噪声是配置不对造成的 bug」
噪声是蒙特卡洛方法的固有性质，来自统计涨落，幅度约 σ/√N。与之相对的是「画面平滑」——它来自几何连续性（相邻像素法线几乎相同）。两者来源完全不同，所以解决手段也完全不同：前者加样本或降噪，后者是几何本身的性质。
