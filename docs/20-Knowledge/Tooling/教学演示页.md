# 教学演示页

> [!abstract] 一句话结论
> `docs/demos/` 下的两页是**单文件、零外部依赖、纯 CPU 计算的交互讲解页**，用途是把知识层的公式落到可操作的像素上。它们是**教学资产，不是引擎实现**，不构成任何 Outcomes 结论。

> [!warning] 边界（先读这一段）
> 页面里的渲染器是**为了让人看见中间状态而写的**（低分辨率帧缓冲、把边缘函数/深度缓冲/覆盖率直接画出来），不是 `Engine/` 的实现，也不代表项目对图形 API、渲染架构或语言标准的选择。引擎侧的唯一事实源仍是 [[10-Outcomes/10-AlphaEngine]]。

## 1. 页面清单

|---|---|---|---|

两页共用同一套呈现约定：**低分辨率帧缓冲 → `putImageData` → `drawImage` 放大（关掉平滑，放大后能看清每个像素方格）**。所有像素由页面自己的 JS 算出，不走 WebGL/GPU——只有这样，边缘函数、覆盖率、深度缓冲、子采样掩码这些**中间状态**才能被画到画布上。两页均无外部 `<script src>`、无外部样式表，可离线单文件打开。

**两页是一组对照**，不是两份独立资料：光追页回答「一条光线怎么去找几何体」，光栅化页回答「一个三角形怎么去找像素」，两页各有一节显式做这件事（光追 §1 / 光栅化 §1 与 §11）。

## 3. 校验约定

每页配一套分层的校验脚本，**改动页面后必须全部重跑**，缺一层就不算验过：

| 层 | 脚本 | 查什么 |
|---|---|---|
| 静态 | `_check.js` | 语法；目录 ↔ 章节 ↔ id 三方一致；控件是否**真的绑了事件监听**（不只是被引用过）；正向守卫 + 反向守卫；字号下限；配色一致性；章节归属（哪些模块允许有 `setState`） |
| 独立 | `verify.raster.js`（112 项）、`verify.math.js`、`verify.dielectric.js`、`verify.render.js` | 用**另行实现**的数学（边缘函数、重心坐标、透视权重、float32 ULP、射线求交真值）重算，再与页面输出逐像素比对 |
| 负向 | `_neg.js`（32 条）、`_neg7.js`、`_neg8.js` | 逐条把页面源码改坏（每次一处），断言必须报错；并含一条**无害改动控制组**，它必须**不被**检出 |
| 冒烟 | `_smoke.js` | 顶层执行 + 数千帧 `requestAnimationFrame` 回调 + 穷举控件事件 + 指针拖动 + `scroll`/`resize`，要求零异常，最后再调页面内建 `verify()` |
| 出图 | `_preview.js`（光栅化） | 把页面**真实帧缓冲**导成 PNG 网格，用非背景像素占比排除「画了一整块背景色」这种假通过 |

### 3.1 三条硬规矩（都是踩过之后立的）

1. **每条断言都要有一个能使它失败的缺陷。** 没有变异对照的断言等于没有断言——负向脚本里那条控制组就是用来证明校验脚本本身还活着（而不是「路径写错、永远退出非 0」导致的假全绿）。变异锚点找不到时必须报失败，绝不当作通过。
2. **常量当探针，验不了「选谁」。** 光栅化 §6 原先用常量色验证反 Z 与标准 Z 等价：共面重叠换赢家时画面有 3637 / 17600 个像素颜色不同，而断言全绿——因为赢家换了、颜色还一样。改成**顶点色**当探针才暴露。凡涉及「多个候选里选了哪个」的性质，探针必须能区分候选。
3. **反向守卫要跑在剥掉注释的源码上。** 否则「记录当年那个 bug 的注释」会被守卫自己命中。

### 3.2 环境约束

- 会话沙箱**可能不允许创建子进程**，届时 `spawnSync` 返回 `EBUSY`，CDP 截图（`_shot.js`）不可用。负向脚本已改为用 `vm.runInNewContext` 在**本进程内**跑校验副本（用桩 `process.exit` 取退出码）；看不到画面时改用「导出真实帧缓冲为 PNG」取证，而不是放弃验画面。
- 单文件页面的校验不要依赖 shell 管道或 coreutils：一律用 Node 绝对路径直接执行脚本。

## 4. 这些页面不构成什么

- **不是引擎实现**：页面里的光追/光栅化内核没有资源绑定、没有 GPU 路径、没有性能目标，目标是「每个中间状态都看得见」。
- **不是技术栈决策**：不涉及图形 API、着色器语言、语言标准的选择；这些仍是 [[10-Outcomes/10-AlphaEngine]] 的待决项。
- **不是基线引用源**：Outcomes 层需要引用数学与架构结论时，引用 Concept 笔记，不引用本页；本页的 `status` 保持 `working`。

## 6. 待核验

- 两页的**软件光栅化内核尚未与 GPU 实现对照**：真实光栅化器的填充规则细节、子像素精度、深度格式（`D32_FLOAT` 等）落地后，应复核光栅化页 §5 / §6 / §10 的结论是否仍然成立。
- 光栅化页 §10 的 4× / 8× MSAA 采样位置表用的是常见排布，选定实际采样模式后需复核。
- 光栅化页 §6 的场景几何（四块板的层高、斜板位置）是按**实测可见像素数**调过的，不是美术摆位；若改动相机或投影参数，必须重跑 `verify.raster.js` 的 J 组（场景良定性）与 `_preview.js`。
- 陷阱卡文案基于页面自身的实测数字；上游公式或约定变化时需同步重跑校验。
- 两页属内部编写，未设来源卡片；若后续引入外部对照资料，按 [[90-System/Schema]] 建 Source 并在此登记。
