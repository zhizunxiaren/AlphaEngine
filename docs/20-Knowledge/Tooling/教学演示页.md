# 教学演示页

> [!abstract] 一句话结论
> `docs/demos/` 下的四页是**单文件、零外部依赖、纯 CPU 计算的交互讲解页**，用途是把知识层的公式落到可操作的像素上。它们是**教学资产，不是引擎实现**，不构成任何 Outcomes 结论。

> [!warning] 边界（先读这一段）
> 页面里的渲染器是**为了让人看见中间状态而写的**（低分辨率帧缓冲、把边缘函数/深度缓冲/覆盖率直接画出来），不是 `Engine/` 的实现，也不代表项目对图形 API、渲染架构或语言标准的选择。引擎侧的唯一事实源仍是 [[10-Outcomes/10-AlphaEngine]]。

光追与光栅化这两页共用同一套呈现约定：**低分辨率帧缓冲 → `putImageData` → `drawImage` 放大（关掉平滑，放大后能看清每个像素方格）**。所有像素由页面自己的 JS 算出，不走 WebGL/GPU——只有这样，边缘函数、覆盖率、深度缓冲、子采样掩码这些**中间状态**才能被画到画布上。四页均无外部 `<script src>`、无外部样式表，可离线单文件打开。

**这两页是一组对照**，不是两份独立资料：光追页回答「一条光线怎么去找几何体」，光栅化页回答「一个三角形怎么去找像素」，两页各有一节显式做这件事（光追 §1 / 光栅化 §1 与 §11）。

平面坐标页与上面两页不同：它不画帧缓冲，只用 canvas 2D 画**平面内的向量与网格**，讲的是「一个点怎么在斜基下读出二维坐标」。这一页的定位是给求交之后的 UV 反解、以及任何非正交基的坐标读取提供直觉，不涉及光照或采样。同样单文件、零外部依赖、可离线打开。

该页的四个场景都由时间驱动：① P 在斜网格内巡游、α/β 实时变化；② 垂直投影落点与真 α 落点分离并标出两者差值；③ α = 0 与 α = 1 两道格线加上 d / h_u 的测距；④ P 沿 v 滑动而 (α·u, v) 平行四边形面积不变。场景可用 `#0`～`#3` 直达，支持拖拽 P 反解坐标、三个基参数滑块与四个图层开关。

## 1.1 基础手册（2026-10-21）

[图形学，慢慢看。](../../../Engine/docs/demos/graphics-basics/index.html) 是新增的基础入口，资产位于当前工作区 Engine/docs/demos/graphics-basics。与上面两份既有单文件演示不同，它由 index.html、style.css、math.js、content.js、pipeline-math.js、pipeline.js、app.js 组成，必须保留同目录文件，可离线直接打开。没有新建第二套 Vault；本笔记仍是资产 owner。

- 12 章、66 个基础概念，每章均有可控实验、四步可点击流程图、类比边界、必要公式与自测。
- 第 04 章新增十阶段光栅化管线连续动画：矩阵变换、六平面齐次裁剪、透视除法、视口、采样覆盖、透视校正属性、着色和深度写入均使用同一场景的实际结果。提供顶点越界/前方挡板开关、时间轴、前后步骤与 0.25× 慢放；不是仅切换步骤文案。
- 动画由用户点击播放，支持暂停、单步、速度和重置；切换页面或进入后台时停止。无自动播放。
- 速查支持中文与英文；复习含 12 个章节题和 66 张概念卡。阅读进度与待复习卡只用浏览器本地存储。
- 现代专题只列十组 TODO，不进入基础篇完成进度。
- 知识入口：[[20-Knowledge/Concepts/图形学基础与渲染流程]]；参考来源：[[30-Sources/图形学基础-教学参考]]。

校验脚本不依赖第三方包。浏览器截图与临时证据放在已忽略的 Engine/output/ 下。数学与内容的静态检查不能代替浏览器冒烟和视觉检查；修改此基础手册时应重跑上述四层，旧光追/光栅化页未修改时不重复执行它们的测试。

## 3. 校验约定

每页配一套分层的校验脚本，**改动页面后必须全部重跑**，缺一层就不算验过：

| 层 | 脚本 | 查什么 |
|---|---|---|
| 静态 | `_check.js` | 语法；目录 ↔ 章节 ↔ id 三方一致；控件是否**真的绑了事件监听**（不只是被引用过）；正向守卫 + 反向守卫；字号下限；配色一致性；章节归属（哪些模块允许有 `setState`） |
| 独立 | `verify.raster.js`（112 项）、`verify.math.js`、`verify.dielectric.js`、`verify.render.js` | 用**另行实现**的数学（边缘函数、重心坐标、透视权重、float32 ULP、射线求交真值）重算，再与页面输出逐像素比对 |
| 负向 | `_neg.js`（32 条）、`_neg7.js`、`_neg8.js` | 逐条把页面源码改坏（每次一处），断言必须报错；并含一条**无害改动控制组**，它必须**不被**检出 |
| 冒烟 | `_smoke.js` | 顶层执行 + 数千帧 `requestAnimationFrame` 回调 + 穷举控件事件 + 指针拖动 + `scroll`/`resize`，要求零异常，最后再调页面内建 `verify()` |
| 出图 | `_preview.js`（光栅化） | 把页面**真实帧缓冲**导成 PNG 网格，用非背景像素占比排除「画了一整块背景色」这种假通过 |

### 3.0 重要采样与 MIS 页（2026-10-23 重写）

这一页原先是一份 194 KB 的单文件散落在 `docs/demos/` 根目录，5 节、2 个画布，只讲到「p 越高越好」和权重公式。重写后收进独立目录，并补上原版缺失的三个关键环节：**换元来源、测度换算、重复计数**。

- 画布：`c1` 重要采样（形状 / f÷p / 收敛三联图）、`c3` 面积→立体角（侧视张开角 + 五个实时读数）、`c2` MIS（分布 / 权重 / 收敛三联图 + 样本明细表）。
- 交互：3 个滑块（贴合度、峰偏移、距离、边长共 4 个）+ 4 个权重模式（简单平均 / 平衡 / 幂 / **直接相加（错）**）。「直接相加」是把权重和做成 2，用来看清 MIS 解决的正是重复计数。
- 权重面板纵轴固定 0~2.2，所以「两条权重之和」这条绿虚线在 1 还是 2 一眼可辨。

| 层 | 脚本 | 查什么 |
|---|---|---|
| 静态 | `node _check.js`（16 项） | 语法；`$('#id')` 全部有对应元素；id 不重复；四种模式按钮齐全；零外部依赖；**同步首帧早于 rAF 注册**（锚定独立成行的 `tick();`，不能锚到 `loop()` 体内那一处）；画布字号 ≥ 11.5px；`p1` 归一到 1 的反向守卫；正文百分比与函数实测值同源；无 `text-transform` |
| 独立数学 | `node _verify.js`（30 项） | ∫p dx = 1（全部滑块组合）；**采样器经验 CDF 与声明的 pdf 一致**（只验归一化不够，两者可以各自正常却不一致）；∫f 的解析式（注意 f 里是未归一化的 exp，∫=σ√2π·截断质量）；方差恒等式 Var=∫f²/p−I²；p∝f 时方差为 0；三种启发式逐点和为 1；平衡启发式 = 样本来源的后验概率；MIS 无偏与 raw = 2I；面积→立体角 p_ω·Ω=1；正文引用的三条量级（0.8 约为均匀的一半、0.95 反而更差、最大贡献 ≈5） |
| 运行时冒烟 | `node _smoke.js`（22 项） | DOM/Canvas 桩内加载零异常；**注册 rAF 之前曲线已画完**（判据用 `lineTo` 段数，不用 API 调用次数）；120 帧；四种权重模式；滑块极值；`d` 从 1 到 4 时 p_ω 涨 16 倍；画布文案无 NaN/undefined；DPR；平衡启发式 400 帧后均值收敛到解析真值 |
| 变异 | `node _neg.js`（14 条，含 1 条无害控制组） | 每条缺陷必须被**指定**断言检出；锚点找不到时报 BROKEN，绝不当作通过 |

变异清单覆盖的缺陷类：p 不归一化、采样器与 pdf 不一致、测度漏 d²、权重用错位置、raw 退化成简单平均、删掉同步首帧、删掉 error 监听、字号过小、id 拼错、少一个模式按钮、CSS 大写化、正文数字与代码脱节、rAF 先于首帧。

`_shot.js` 用 CDP 截图（`node _shot.js <html> <out.png> [选择器] [序号] [缩放] ["dx,dy,w,h"]`）。**不要用 `chrome --screenshot`**：本页首帧由内联脚本绘制，会抓到空白帧。

### 3.1 三条硬规矩（都是踩过之后立的）

1. **每条断言都要有一个能使它失败的缺陷。** 没有变异对照的断言等于没有断言——负向脚本里那条控制组就是用来证明校验脚本本身还活着（而不是「路径写错、永远退出非 0」导致的假全绿）。变异锚点找不到时必须报失败，绝不当作通过。
2. **常量当探针，验不了「选谁」。** 光栅化 §6 原先用常量色验证反 Z 与标准 Z 等价：共面重叠换赢家时画面有 3637 / 17600 个像素颜色不同，而断言全绿——因为赢家换了、颜色还一样。改成**顶点色**当探针才暴露。凡涉及「多个候选里选了哪个」的性质，探针必须能区分候选。
3. **反向守卫要跑在剥掉注释的源码上。** 否则「记录当年那个 bug 的注释」会被守卫自己命中。

### 3.2 环境约束

- 会话沙箱**可能不允许创建子进程**，届时 `spawnSync` 返回 `EBUSY`，CDP 截图（`_shot.js`）不可用。负向脚本已改为用 `vm.runInNewContext` 在**本进程内**跑校验副本（用桩 `process.exit` 取退出码）；看不到画面时改用「导出真实帧缓冲为 PNG」取证，而不是放弃验画面。
- 单文件页面的校验不要依赖 shell 管道或 coreutils：一律用 Node 绝对路径直接执行脚本。

## 4. 这些页面不构成什么

- **不是引擎实现**：页面里的光追/光栅化内核没有资源绑定、没有 GPU 路径、没有性能目标，目标是「每个中间状态都看得见」。
- **不是技术栈决策**：不涉及图形 API、着色器语言、语言标准的选择；这些仍是 [[10-Outcomes/10-AlphaEngine]] 的待决项。
- **不是基线引用源**：Outcomes 层需要引用数学与架构结论时，引用 Concept 笔记，不引用本页；本页的 `status` 保持 `working`。

## 6. 待核验

- 两页的**软件光栅化内核尚未与 GPU 实现对照**：真实光栅化器的填充规则细节、子像素精度、深度格式（`D32_FLOAT` 等）落地后，应复核光栅化页 §5 / §6 / §10 的结论是否仍然成立。
