## 1. 射线与球体求交

### 1.1 推导

**射线**由起点与方向参数化：

```
P(t) = O + t·D              t ∈ [0, ∞)
```

**球面**是到球心距离等于半径的点集：

```
|X - C|² = r²
```

把 `P(t)` 代入并展开。令 `oc = C - O`（由射线起点指向球心的向量）：

```
|t·D - oc|² = r²
t²(D·D) - 2t(D·oc) + (oc·oc - r²) = 0
```

这是关于 `t` 的一元二次方程，三个系数各对应一个几何量：

| 系数 | 表达式 | 含义 |
|---|---|---|
| `a` | `D·D` | 方向向量的**平方长度**（未归一化时不为 1） |
| `h` | `D·oc` | 方向与「起点 → 球心」的投影（**半 b 形式**，标准式里 `b = -2h`） |
| `c` | `oc·oc - r²` | `c < 0` 当且仅当**起点位于球内部** |

> **半 b 形式**：标准求根公式 `t = [-b ± √(b²-4ac)] / 2a` 代入 `b = -2h` 后可整体约掉因子 2，得到 `t = [h ± √(h²-ac)] / a`。系数与判别式都少一次乘法，是图形学中的标准写法。

**判别式** `Δ = h² - a·c`，**两根**：

```
t = (h ± √Δ) / a
```

| 判别式 | 几何含义 |
|---|---|
| `Δ < 0` | 射线与球**不相交** |
| `Δ = 0` | 射线与球**相切**（重根） |
| `Δ > 0` | **两个交点**——穿入点与穿出点 |

### 1.2 两条根的含义

因为 `a > 0`，所以 `(h - √Δ)/a ≤ (h + √Δ)/a`：

```
        相机
         ●────────────→        ┌───────────┐
                  t₁ ↗         │    球      │  ↘ t₂
                               └───────────┘
      t₁ = (h - √Δ)/a  ← 近根，穿入点
      t₂ = (h + √Δ)/a  ← 远根，穿出点
```

渲染时应当取**近根**——光线先撞到的那一面。但有两种情形需要回退到远根或直接排除：

| 情形 | 条件 | 结果 |
|---|---|---|
| 起点在球外、球在前方 | `c > 0` 且 `h > 0` | 两根皆正，取近根 |
| 球在相机背后 | `c > 0` 且 `h < 0` | 两根皆负，未命中 |
| **起点在球内部** | `c < 0` | 近根为负、远根为正，**必须取远根** |
| 起点在球面上 | `c = 0` | 一根为 0，一根为正 |

> `c < 0` 等价于 `|C - O| < r`，即相机落在球体内——这是"相机可以进入几何体"这类场景（例如体积、开放场景漫游）必须支持的路径。

### 1.3 根的范围筛选

求交不能只看"有没有解"，还要看解是否落在**允许的参数范围**内。有效范围是**开区间**：

```
t_min < t < t_max
```

筛选逻辑是"**先近后远，都不行才算未命中**"：

```
root ← (h - √Δ) / a
if root 不在 (t_min, t_max):
    root ← (h + √Δ) / a
    if root 也不在 (t_min, t_max):
        未命中
```

用比较运算表达"不在范围内"（即对 `t_min < t < t_max` 取反）：

```
root <= t_min  ||  root >= t_max
```

`t_min` 与 `t_max` 各有明确用途：

- **`t_min`** —— 剔除自交。次级光线（阴影、反射、折射）从表面出发，必须跳过 `t ≈ 0` 处与自身表面的伪交
- **`t_max`** —— 限制搜索深度。任何更远的交点已经不可能是最近的表面

### 1.4 法线与朝向

**外法线**由「交点 − 球心」归一化得到：

```
N = (P - C) / r
```

交点在球面上，所以 `|P - C| = r`，除以 `r` 恰好归一化，无需再调 `unit_vector`。

**朝向必须规范化。** 外法线总是朝球外，但光线的来向不一定：

| 情形 | `dot(D, N)` | 处理 |
|---|---|---|
| 光线从外部射入 | `< 0` | 法线与光线反向，**保持不变** |
| 光线从内部射出 | `> 0` | 法线与光线同向，**翻转为 `-N`** |

同时记录一个 `front_face` 布尔量，供后续材质判断"看到的是正面还是背面"。**若只赋外法线而不做翻转，从几何体内部观察到的着色会整体反相。**

### 1.5 边界与陷阱

- **区间是开的。** 有效判据是 `t_min < t < t_max`；写成 `t_min <= t <= t_max` 会改变边界语义，导致贴面自交或边界处重复命中。
- **比较方向易写反。** 判据里是 `root >= t_max` 而不是 `root <= t_max`。写成 `<=` 时该子条件恒为真，使"不在范围内"永远成立——表现为**几何体完全无法被渲染**。若 `t_max` 取无穷大，这种错误尤其隐蔽：它不会报错，只是画面里什么都没有。
- **方向向量未归一化时 `t` 不是距离。** 射线方向若由"像素位置 − 相机位置"直接给出，则 `a = |D|² ≠ 1`，`t` 只是参数不是欧氏距离。这不影响解的正确性（`t` 仅用于排序与求点），但会影响 `t_min` / `t_max` 的取值直觉——按距离设定的阈值会随像素位置漂移。
- **零半径会污染法线。** 半径若被钳制为 0，`(P - C) / r` 会除零得到 NaN。应在求交入口直接拒绝非正半径，而不是让 NaN 扩散到着色阶段。
- **哨兵返回值表达力不足。** 用 `-1` 表示"未命中"，无法区分"未命中"与"命中但参数为负"，调用方还必须记住这条约定。正解是返回 `bool`，命中信息经输出参数带回。
- **相切附近对精度敏感。** `Δ ≈ 0` 时浮点误差会让"擦过"变成"未命中"或产生极小 `a`。远距离物体的表面可能出现噪点或漏缝。

### 1.6 在渲染器中的落点

| 场景 | 做法 |
|---|---|
| 求交接口 | 返回 `bool`，命中信息（`t`、交点、法线、`front_face`）经输出参数带回，而非哨兵返回值 |
| 允许穿入几何体 | 必须实现"近根不在范围内则回退远根"的路径 |
| 法线朝向 | 强制法线与光线反向并记录 `front_face`，供材质区分正反面 |
| 自交剔除 | 次级光线用 `t_min > 0` 跳过出发面 |
| `t` 的语义 | 若方向未归一化，`t_min` / `t_max` 不能按物理距离设定 |

> 后续发展方向：单个求交函数会被 `hittable` 抽象取代——虚接口返回 `bool` 并填充 `hit_record`，再由 `hittable_list` 组合出任意场景。本页只记录数学，接口设计在形成体系后另立章节。

## 2. 射线与平面、有限四边形求交

### 2.1 平面方程与 `t` 的解

平面的点集式：

```
n·X = D          D = n·Q        （D 是「法向在基点 Q 上的读数」）
```

代入 `P(t) = O + t·D`：

```
n·(O + t·D) = D
t = (D − n·O) / (n·D)
```

| 量 | 含义 |
|---|---|
| 分子 `D − n·O` | 起点到平面的**有符号法向距离**（`n` 未归一化时多带一个 `\|n\|` 因子） |
| 分母 `n·D` | 方向在法向上的读数；`n·D = 0` ⇔ 射线**平行于平面** |

`|n·D|` 趋零时 `t` 发散——掠射角处的漏缝与噪点由此而来，与 §1.5「相切附近对精度敏感」同源。

> `n` 是否归一化不改变 `t`（分子分母同乘因子会约掉），但**会改变**「`|n·D|` 小于某阈值」这一判据的量纲。见 2.6。

### 2.2 `t` 只把交点定位到无限大平面

这是本节最容易踩的认知坑：**解出的 `t` 与「这块面有多大」毫无关系**。

有限四边形的完整定义是 `(Q, u, v)`，但构造平面方程时只用到其中一部分：

```
n      = cross(u, v)
normal = unit_vector(n)     ← u、v 的长度在这里被归一化掉了
D      = dot(normal, Q)     ← 只用到 Q 的位置
```

`u` 是 1 米还是 100 米，`normal` 与 `D` 完全相同。也就是说，**在算 `t` 的那一刻，边界信息已经不在式子里了**。解出来的必然是「射线与那张无限大平面的交点」：它保证点在平面上，不保证点在框里。

同一张平面上可以贴任意大小的四边形，它们共享 `Q`、`normal`、`D`，同一条射线解出**同一个 `t`**，但内部判定完全相反：

```
命中点 p = 1.8·u + 0.4·v

quad₁（边 u, v）    : α = 1.8          → α > 1，不命中
quad₂（边 2u, 2v）  : α = 0.9, β = 0.2 → 命中
```

即：**`t` 那一步消费的是 quad 的位置与朝向，`α、β` 那一步消费的是 quad 的大小**。两者合起来才是完整定义。

### 2.3 为什么必须分两步

不是实现习惯，是**代数结构决定的**：

| 步骤 | 数学性质 | 能做什么 |
|---|---|---|
| 解 `t` | 一个等式、一个未知量 | **解**出唯一交点 |
| 判内部 | 四个不等式（`0 ≤ α ≤ 1`、`0 ≤ β ≤ 1`） | 只能把点**代进去验** |

不等式不是解出来的。所以任何算法的骨架都是：**先用便宜的必要条件过滤（在平面上），再验充分条件（在框里）**。同一结构在别处反复出现：

- BVH / AABB：先测包围盒（必要非充分），再测图元；
- 三角形 Möller–Trumbore：把 `(t, u, v)` 合成一个 3×3 线性系统一次解出，但解完**仍然要验** `u ≥ 0`、`v ≥ 0`、`u + v ≤ 1`——两步结构不变，只是把「读坐标」和「解 `t`」合并了。

反过来做（遍历图元上的点去问落在哪个像素）是光栅化的方向。光线追踪是「射线问几何体」，因此 `hit()` 返回 `false` 是常态而非异常——屏幕上绝大多数射线打不到任一给定图元。

### 2.4 平面坐标：第二步读什么

令 `p = 交点 − Q`，所求即 `p = α·u + β·v` 里的 `(α, β)`。叉积消元给出：

```
p × v = (αu + βv) × v = α(u×v) + β(v×v) = α·n        （v×v = 0，β 自动消掉）
n·(p×v) = α·(n·n)  ⇒  α = w·(p×v) ,   w = n/(n·n)

同理  u × p = β·n   ⇒  β = w·(u×p)
```

几何含义是**带符号面积比**：`α = 面积(p,v) / 面积(u,v)`（Cramer 法则：把基里 `u` 那一列换成 `p`）。完整推导、对偶基形式与可手算算例见 [[20-Knowledge/Concepts/对偶基与平面坐标#7.1 命中四边形 → 纹理坐标（本仓库 Engine/quad.h）|对偶基与平面坐标 · 7.1]]，本页不重复。

因为 `u`、`v` 是**整条边**，参数域天然是单位正方形，`α、β` 直接就是 UV，**不需要再归一化**——这是很多人白写一次除法的原因。

### 2.5 算例

quad = `z = −1` 平面上 `x,y ∈ [−0.5, 0.5]` 的单位方块：`Q = (−0.5, −0.5, −1)`、`u = (1,0,0)`、`v = (0,1,0)`、`n = (0,0,1)`、`D = −1`。相机在原点，某像素射线方向 `(1.8, 0.3, −1)`：

```
t    = (D − n·O)/(n·dir) = (−1 − 0)/(−1) = 1
交点 = (1.8, 0.3, −1)
p    = 交点 − Q = (2.3, 0.8, 0)
α = 2.3, β = 0.8     → α > 1，不在 quad 内
```

`x = 1.8` 在方块右边界 `0.5` 之外两米多，但在 `z = −1` 这张无限平面上一点没错。**若去掉内部判定，这个单位方块会被渲染成一张无限大的平面**——这就是第二步存在的物理含义。

### 2.6 边界与陷阱

- **叉积顺序不能反。** 必须是 `cross(p, v)` 与 `cross(u, p)`。写成 `cross(v, p)` / `cross(p, u)` 会整体差一个负号，症状是 UV 翻转、判定区跑到对角。
- **`w = n/(n·n)` 不是 `n/\|n\|`。** 目的是把面积比归一化成无量纲：量纲上 `n` 是 `L²`、`n·n` 是 `L⁴`、`w` 是 `L⁻²`，乘上 `L²` 的叉积正好约掉。
- **内部判定不能省、不能与 `t` 的判据混为一谈。** `t` 落在 `(t_min, t_max)` 内不代表命中图元；反之命中也不代表 `t` 在允许范围内。两个判据互不蕴含。
- **退化要在用之前挡住。** `u ∥ v` 时 `n·n → 0`，`w` 直接发散，画面表现为「这块面糊成一色」而不是报错。判据用 `(n·n) > eps·(u·u)·(v·v)`（实为 `sin²θ`，见对偶基页 §7.5），不要等除出 `inf` 再查。
- **平行判据要无量纲。** `fabs(denom) < 1e-8` 只有在 `n` 与射线方向都已归一化时才是角度判据；否则它随场景尺度漂移，等价于拿一个有量纲的数与常数比较。
- **`α、β` 的合法域是闭区间 `[0,1]`。** 与 §1.3 的 `t` 用开区间不同——边缘上的点属于图元，改成开区间会让接缝处出现针孔。

### 2.7 在渲染器中的落点

| 场景 | 做法 |
|---|---|
| 求交接口 | 平面求交与内部判定拆成两个函数：`hit()` 解 `t`，另有一个只管 `(α, β)` 的判定函数。**子类只覆写后者即可换形状**，平面求交逻辑完全复用 |
| 形状变体 | 同一套 `(Q, u, v)` 下，三角形用 `a ≥ 0, b ≥ 0, a + b ≤ 1`；椭圆用 `a² + b² ≤ 1`；圆环用 `inner ≤ √(a²+b²) ≤ 1` |
| UV 产出 | `α、β` 直接写入 `rec.u / rec.v`；当基是半轴、参数域为 `[-1,1]` 时（椭圆 / 圆环）才需要 `a/2 + 0.5` 折回 `[0,1]` |
| 包围盒 | 由 `Q, Q+u+v` 与 `Q+u, Q+v` **两条对角线各自的 AABB 并成**；只取一条对角线在斜基下会漏掉角点 |
| 退化防护 | 构造期挡住 `u ∥ v`，使 `w` 的除法只在通过后才发生 |

> 形状变体一栏的具体判据取自本仓库 `Engine/quad.h` 的现有实现形态（`quad` / `tri` / `ellipse` / `annulus`），属**事实登记**；实现细节的取舍由作者决定，本页只记录它们共享的两步结构。
