# 现代渲染器高级能力矩阵

## 一句话结论

AlphaEngine MVP 2 应交付可度量的现代 D3D12 渲染能力，而不是把可选硬件 API 当成产品结果：每项高级能力必须有稳定的上层语义、运行时能力查询、质量与性能验收，以及不支持该能力时仍能正确渲染的 fallback（回退路径）。MVP 3 再用 Vulkan 对这些上层语义做功能对等验证。

## 边界与证据说明

### 项目已确认范围

- MVP 2 在 D3D12 后端实现现代高级渲染能力；MVP 3 再实现 Vulkan 功能对等。
- MVP 2 包含本文核对的 GPU-driven/ExecuteIndirect、Mesh Shader、VRS、Sampler Feedback、Enhanced Barriers、Work Graphs、Residency/Streaming 与 Pipeline Library。
- 硬件光线追踪不在当前范围内。
- “实现高级能力”指每个能力域有一个可投入使用、可测试的结果，不要求把所有可选算法都实现一遍。
- Vulkan 列是 MVP 3 的等价策略与 seam（接口接缝）约束，不代表 MVP 2 同时开发 Vulkan。

以上是项目决策，不是 Microsoft 或 Khronos 的产品承诺。

### 官方能力事实的使用规则

- Feature Level（功能级别）不等于全部可选能力；启动时必须逐项查询 feature/tier/property，不能只检查 GPU 型号。
- 高级路径不得成为正确性的唯一来源。fallback 必须产生语义等价的可接受画面，只允许性能或精度分级。
- 性能收益不能从 API 名称推导；所有“更快”结论必须来自同一场景、同一画质、同一机器的 A/B 数据。

| Sampler Feedback | 纹理 tile/mip 需求由 GPU 观测驱动，显存压力下仍无未驻留采样错误和明显闪烁 | 查询 `D3D12_FEATURE_D3D12_OPTIONS7.SamplerFeedbackTier`；Tier 0.9/1.0 均可用但限制不同；官方建议可工作的 streaming 配套 Tiled Resources Tier 2 | Reserved/tiled texture + MinMip/feedback map + feedback resolve/readback + copy queue tile upload + `UpdateTileMappings`；用 budget 控制驻留 | Vulkan 没有与 D3D12 feedback map 完全一一对应的核心机制；使用 sparse image/residency + shader 侧反馈缓冲，或纯启发式需求估计；查询 `sparseResidencyImage2D` 等 feature | 规定镜头轨迹下不得读取未映射 tile；统计 requested/resident/missing tile、反馈延迟、上传带宽、显存峰值；与启发式路径比较画质收敛时间和开销 | 屏幕投影/距离启发式的 mip streaming；不支持 sparse 时使用普通纹理按整 mip 或整资源替换 |

| Work Graphs | 对动态扩张、producer-consumer 的 compute 工作负载实现 GPU 内部调度，减少 CPU dispatch 链和中间缓冲最坏情况预留 | `D3D12_FEATURE_D3D12_OPTIONS21.WorkGraphsTier >= 1.0`；正式版使用 Shader Model 6.8、Agility SDK 1.613+；当前 Tier 1.0 的稳定范围是 compute-like node，graphics nodes 不作为验收依赖 | Node shader library (`lib_6_8`) + state object/work graph + backing memory + `DispatchGraph`；只迁移确有动态扩张收益的 workload | 当前没有一对一的 Vulkan 标准 work-graph 模型；以普通 compute pass 图、indirect dispatch/draw 和可选 `VK_EXT_device_generated_commands` 实现结果等价 | 与 compute-pass fallback 输出逐项一致；覆盖零输入、爆发式扩张、backing memory 边界；比较 CPU 提交、临时显存、同步开销和 GPU 总时长 | Render Graph 编排的 compute chain + UAV barriers + ExecuteIndirect/DispatchIndirect；该路径也是跨 API 语义基准 |
| Residency / Streaming | 在可变显存 budget 下管理 texture/mesh 的加载、驻留、淘汰与同步，不因超预算产生长时间卡顿或错误访问 | Budget 来自 `IDXGIAdapter3::QueryVideoMemoryInfo` 并可订阅变化；heap/committed-resource residency 由 MakeResident/Evict 管理；细粒度 partial residency 还需查询 Tiled Resources tier | Residency manager 跟踪每次提交所需 heap、last-use fence、优先级和 LRU；`EnqueueMakeResident` + fence；Copy Queue 上传；reserved resource 做 tile 级 streaming | `VK_EXT_memory_budget`（若可用）报告预算；普通 `VkDeviceMemory` 分配/淘汰与 sparse resource 的 `vkQueueBindSparse` 分层实现；逐项查询 sparse feature/format | 人工收紧 budget、窗口切换与快速镜头压力测试；零 device removed/未驻留访问；记录 budget、usage、resident bytes、eviction、上传队列延迟和 hitch 分位数 | 限制资产质量/工作集；whole-resource streaming；placed/committed resource；禁用 partial residency 但保持正确渲染 |
| Pipeline Library / PSO Cache | 消除运行时首次遇到材质/变体时的可感知 PSO 编译卡顿，并能安全丢弃失效缓存 | 查询 `D3D12_FEATURE_SHADER_CACHE`，要求 `D3D12_SHADER_CACHE_SUPPORT_LIBRARY`；序列化 blob 与其他硬件/设备不可移植，runtime/driver 更新会使其失效 | 稳定 PSO key + `ID3D12PipelineLibrary` Load/Store/Serialize；缓存头记录 adapter、driver/runtime、shader 与 root-signature 版本；后台预热 | 基线 `VkPipelineCache`；可选 `VK_EXT_graphics_pipeline_library` 拆分/链接；Vulkan 1.4 或扩展支持时可用 `VK_KHR_pipeline_binary` 自管二进制 | cold/warm 两轮统计 PSO 创建时间、cache hit/miss 和帧时间 p95/p99；驱动、shader、root signature 变化后必须正确 invalidation；损坏缓存可恢复 | 无命中时从 shader/PSO 描述正常创建并回填；功能绝不能依赖缓存存在 |

## 官方能力事实核对

### 1. GPU-driven 与 ExecuteIndirect

- Microsoft 将 indirect drawing 定义为把一部分 scene traversal（场景遍历）和 culling（剔除）移到 GPU；argument buffer 可由 CPU 或 GPU 生成，command signature 定义参数格式、命令类型和每命令可变绑定。[Microsoft Learn：Indirect Drawing](https://learn.microsoft.com/en-us/windows/win32/direct3d12/indirect-drawing)
- `ExecuteIndirect` 可从 count buffer 读取实际命令数，并以 `min(count, MaxCommandCount)` 为执行上限；argument/count buffer 必须处于 indirect-argument 状态。[Microsoft Learn：ID3D12GraphicsCommandList::ExecuteIndirect](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12graphicscommandlist-executeindirect)
- DirectX 规范说明所有 D3D12 device 支持 ExecuteIndirect Tier 1.0；Tier 1.1 增加 Incrementing Constant，需要通过 `D3D12_FEATURE_D3D12_OPTIONS21` 查询。[DirectX Specs：Indirect Drawing](https://microsoft.github.io/DirectX-Specs/d3d/IndirectDrawing.html)
- Vulkan 的 `vkCmdDrawIndirectCount`/`vkCmdDrawIndexedIndirectCount` 允许 draw count 在执行时由 buffer 决定；扩展已提升到 Vulkan 1.2，但仍需检查 `drawIndirectCount` feature。[Khronos：VK_KHR_draw_indirect_count](https://docs.vulkan.org/guide/latest/extensions/VK_KHR_draw_indirect_count.html)
- `VK_EXT_device_generated_commands` 能表达比普通 indirect draw/dispatch 更广的 device-generated command stream，但官方规范也指出：只有一个 action token 时，普通 indirect path 在某些实现上可能更快。[Khronos：Device-Generated Commands](https://docs.vulkan.org/spec/latest/chapters/device_generated_commands/generatedcommands.html)

### 2. Mesh Shader

- D3D12 Mesh Shader 用 Amplification/Mesh Shader 取代传统 pre-rasterization stages（预光栅阶段），Mesh Shader 以 threadgroup 运行并直接输出 vertices/primitives；支持由 `D3D12_FEATURE_D3D12_OPTIONS7.MeshShaderTier` 查询。[DirectX Specs：Mesh Shader](https://microsoft.github.io/DirectX-Specs/d3d/MeshShader.html)
- 官方规范明确建议可把 meshlet 转成常规 index buffer，作为 vertex-shader fallback；因此 meshlet 资产布局不应绑定到 `DispatchMesh`。[DirectX Specs：Mesh Shader](https://microsoft.github.io/DirectX-Specs/d3d/MeshShader.html)
- Vulkan 的已 ratify（批准）扩展 `VK_EXT_mesh_shader` 提供 task/mesh stages，以及 direct、indirect 和 indirect-count 的 mesh task draw 命令。[Khronos：VK_EXT_mesh_shader](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_mesh_shader.html)

### 3. Variable Rate Shading

- D3D12 VRS 通过 coarse pixel shading（粗粒度像素着色）减少 pixel-shader invocation；Tier 1 与 Tier 2 能力不同，应用必须查询 `D3D12_FEATURE_D3D12_OPTIONS6`，并同时考虑 MSAA、额外 shading rate 和 tile size 限制。[DirectX Specs：Variable Rate Shading](https://microsoft.github.io/DirectX-Specs/d3d/VariableRateShading.html)
- Vulkan `VK_KHR_fragment_shading_rate` 将 per-draw、per-primitive 与 attachment/per-region 能力拆成独立 feature，并允许枚举 rate 与 sample-count 组合；不能假设 D3D12 的 combiner 编码可直接复用。[Khronos：VK_KHR_fragment_shading_rate](https://docs.vulkan.org/features/latest/features/proposals/VK_KHR_fragment_shading_rate.html)

### 4. Sampler Feedback

- Sampler Feedback 记录纹理采样位置/细节需求，官方列出 streaming 与 texture-space shading 两类用途；支持等级通过 `D3D12_FEATURE_D3D12_OPTIONS7.SamplerFeedbackTier` 查询，且不由某个 D3D feature level 强制保证。[DirectX Specs：Sampler Feedback](https://microsoft.github.io/DirectX-Specs/d3d/SamplerFeedback.html)
- 官方 streaming 流程使用 reserved/tiled texture、MinMip map 与 feedback map，并推荐 Tiled Resources Tier 2 作为可工作的依赖；即使没有 Sampler Feedback，D3D12 仍可自行用 tiled resource 渐进加载 mip。[DirectX Specs：Sampler Feedback](https://microsoft.github.io/DirectX-Specs/d3d/SamplerFeedback.html)
- Vulkan sparse resource 支持非连续绑定、重绑定和部分驻留，但这些 feature 必须逐项启用；`vkQueueBindSparse` 还需要应用显式同步。[Khronos：Sparse Resources](https://docs.vulkan.org/guide/latest/sparse_resources.html)
- “Vulkan 用 shader feedback buffer 实现需求观测”是本项目的等价策略，不是 Khronos 定义的 D3D12 Sampler Feedback 一对一 API。

### 5. Enhanced Barriers

- Enhanced Barriers 把 synchronization、access 与 texture layout 分开表达，并提供 Global/Buffer/Texture 三类 barrier；它不是硬件或驱动强制能力，必须查询 `D3D12_FEATURE_D3D12_OPTIONS12.EnhancedBarriersSupported`。[DirectX Specs：Enhanced Barriers](https://microsoft.github.io/DirectX-Specs/d3d/D3D12EnhancedBarriers.html)
- Legacy `ResourceBarrier` 仍然有效，二者可以互操作；但官方建议尽量避免在同一 subresource 混用，因为可能产生额外开销。[DirectX Specs：Enhanced Barriers](https://microsoft.github.io/DirectX-Specs/d3d/D3D12EnhancedBarriers.html)
- Vulkan `VK_KHR_synchronization2` 把 stage 与 access 放进同一组 barrier 结构并改进 image transition/queue submit，已提升到 Vulkan 1.3 core。[Khronos：VK_KHR_synchronization2](https://docs.vulkan.org/guide/latest/extensions/VK_KHR_synchronization2.html)

### 6. Work Graphs

- 正式版 D3D12 Work Graphs 随 Agility SDK 1.613 和 Shader Model 6.8 发布，node shader 使用 `lib_6_8`，支持 GPU producer 请求 consumer 工作并由系统调度。[Microsoft DirectX Developer Blog：D3D12 Work Graphs](https://devblogs.microsoft.com/directx/d3d12-work-graphs/)
- 支持等级通过 `D3D12_FEATURE_D3D12_OPTIONS21.WorkGraphsTier` 查询；Tier 1.0 是首个正式等级。规范把 graphics nodes 标为尚未支持的 proposed（提案）内容，所以 MVP 2 不应依赖 preview mesh/graphics node。[DirectX Specs：Work Graphs](https://microsoft.github.io/DirectX-Specs/d3d/WorkGraphs.html)
- `ExecuteIndirect` 是受约束的 GPU-generated work，而 Work Graphs 表达 node 间动态 producer-consumer 调度；二者相关但不等价。[Microsoft DirectX Developer Blog：D3D12 Work Graphs](https://devblogs.microsoft.com/directx/d3d12-work-graphs/)

### 7. Residency 与 Streaming

- D3D12 residency 表示 heap/resource 是否可被 GPU 访问。应用需要知道提交会使用哪些 heap、在使用前使其 resident，并等待 GPU 完成后才可 evict；微软 Starter Library 以每 command list 的 residency set 展示这套职责。[Microsoft Learn：D3D12 Residency Starter Library](https://learn.microsoft.com/en-us/samples/microsoft/directx-graphics-samples/d3d12-residency-starter-library-win32/)
- `IDXGIAdapter3::QueryVideoMemoryInfo` 报告进程的当前 budget 与 usage，并能注册 budget-change notification。[Microsoft Learn：IDXGIAdapter3](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nn-dxgi1_4-idxgiadapter3)
- `ID3D12Device3::EnqueueMakeResident` 异步使对象驻留并在完成时 signal fence；引用这些对象的 GPU 工作不能在该 fence signal 前执行。[Microsoft Learn：EnqueueMakeResident](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device3-enqueuemakeresident)
- D3D12 reserved resource 只保留虚拟地址，需用 `UpdateTileMappings`/`CopyTileMappings` 映射物理 heap；不支持时 placed resource 是正确但不可部分驻留的 fallback。[Microsoft Learn：Memory Management Strategies](https://learn.microsoft.com/en-us/windows/win32/direct3d12/memory-management-strategies)
- Vulkan sparse residency 允许 image/buffer 未完全绑定，并可在 block/subresource 粒度重新绑定；实际 2D/3D/MSAA/aliasing 能力由独立 feature 和 format property 决定。[Khronos Vulkan Spec：Sparse Resources](https://docs.vulkan.org/spec/latest/chapters/sparsemem.html)

### 8. Pipeline Library 与 PSO Cache

- `ID3D12PipelineLibrary` 支持 Store、Load、GetSerializedSize 与 Serialize；是否支持 library 要检查 `D3D12_FEATURE_SHADER_CACHE` 的 `D3D12_SHADER_CACHE_SUPPORT_LIBRARY`。[Microsoft Learn：CreatePipelineLibrary](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device1-createpipelinelibrary)
- 序列化 library 可供后续进程加载，但 blob 在 runtime/driver 更新后失效，也不能迁移到其他 hardware/device。[Microsoft Learn：ID3D12PipelineLibrary::Serialize](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12pipelinelibrary-serialize)
- Vulkan `VK_EXT_graphics_pipeline_library` 允许把 graphics pipeline 分段编译并链接，目标是降低大量材质或动态材质流送时的 pipeline compilation 开销。[Khronos：VK_EXT_graphics_pipeline_library](https://docs.vulkan.org/features/latest/features/proposals/VK_EXT_graphics_pipeline_library.html)
- Vulkan `VK_KHR_pipeline_binary` 允许应用获取并管理单个 pipeline 的 implementation-specific binary；它要求 Vulkan 1.4 或列出的扩展依赖，不能作为 MVP 3 的无条件基线。[Khronos：VK_KHR_pipeline_binary](https://docs.vulkan.org/refpages/latest/refpages/source/VK_KHR_pipeline_binary.html)

## 跨后端设计约束

上层 Renderer/Render Graph 应表达结果和资源意图，不暴露以下 API 私有概念：

```text
Renderer Result / Render Graph Intent
  ├─ Visible work list / LOD decision
  ├─ Geometry work item / meshlet
  ├─ Shading-rate intent
  ├─ Texture residency request
  ├─ Sync + access + layout intent
  ├─ Dynamic compute work graph
  └─ Pipeline description + stable cache key

D3D12 Adapter                 Vulkan Adapter
  ExecuteIndirect               DrawIndirectCount / DGC
  DispatchMesh                  VK_EXT_mesh_shader
  VRS                           VK_KHR_fragment_shading_rate
  Sampler Feedback              Sparse + shader feedback/heuristic
  Enhanced Barriers             Synchronization2
  Work Graphs                   Compute graph + indirect/DGC
  Residency/Tiled Resources     Budget + sparse resources
  Pipeline Library              Pipeline cache/library/binary
```

禁止把 `D3D12_RESOURCE_STATES`、root signature、command signature、feedback-map encoding 或 Work Graph node ABI 放进跨后端接口。跨后端测试以结果、依赖和生命周期为准，不追求 API 调用的一一映射。

## 统一验收门槛

每项能力进入“完成”状态前至少满足：

1. **Capability test**：启动时记录真实 feature/tier/limit，并能强制关闭高级路径。
2. **Correctness test**：高级路径与 fallback 在确定性场景中产生等价结果；Debug Layer、GPU validation 与 Vulkan Validation（MVP 3）无 error。
3. **Stress test**：覆盖零工作、最大工作量、快速相机切换、resize、显存压力、shader/cache 失效和 device-lost 诊断。
4. **Performance test**：同硬件、同画质、同场景做 A/B；记录 CPU frame、GPU frame、相关 pass、显存、带宽和 hitch percentile，不只看平均 FPS。
5. **Fallback test**：通过软件开关模拟 feature 缺失；不能 crash、访问未驻留资源或出现未定义画面。
6. **Observability**：PIX marker、timestamp、资源/命令计数与运行时 feature report 足以解释路径选择和性能差异。

具体数值阈值（目标显卡、分辨率、场景、画质容差、最低收益百分比）仍需在 MVP 2 性能基线确定后填写，当前不得虚构。

## 事实、项目推断与待决定问题

### 已确认的官方事实

- 本文八项 D3D12 能力中，Mesh Shader、VRS、Sampler Feedback、Enhanced Barriers、Work Graphs、Tiled/partial residency 与 Pipeline Library 都存在必须显式查询的 tier/feature/support flag。
- ExecuteIndirect 基础 Tier 1.0 是 D3D12 基线；它与 Work Graphs 的动态 node 调度不是同一种抽象。
- Vulkan 对 Mesh Shader、VRS、Synchronization2、sparse resource 和 pipeline compilation/caching 有官方扩展或 core 路径，但对 D3D12 Sampler Feedback 与 Work Graphs 没有完全一一对应的标准对象模型。

### 本项目的设计推断

- Render Graph 应成为 barrier 两条路径与跨 API synchronization 的单一事实来源。
- GPU-driven、Mesh Shader 与 Work Graphs 应建立在同一 API-neutral GPU Scene/meshlet/work-item 数据上，避免三套场景表示。
- Sampler Feedback、VRS、Work Graphs 和 Pipeline Library 都是可选加速路径，不应决定资产是否能被正确显示。
- Vulkan MVP 3 的目标是结果和能力域对等；允许用不同底层算法达成，不追求 D3D12 API 逐函数仿真。

### 待决定问题

- MVP 2 最低参考 GPU、显存、分辨率和目标帧率。
- 哪些高级能力是最低硬件门槛，哪些必须保留可发布 fallback。
- 每项 A/B 性能收益的启用阈值与图像容差。
- Work Graphs 首个落地 workload，以及它是否比普通 compute/indirect 路径有稳定收益。
- Texture streaming 的 tile 大小、反馈延迟、显存安全余量和 IO/解压路径。
- Vulkan MVP 3 的最低版本是 1.3 还是 1.4；这会影响 pipeline binary 是否可作为基础能力。
